# Future FS CRM

This repo contains a Node/Express backend and a Vite/React frontend.

## Local development

### Backend

```bash
cd backend
npm install
npm run dev
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Your frontend will use `VITE_API_URL` from `frontend/.env.local` when running locally.

## Docker deployment

### Build and run locally

```bash
docker compose up --build
```

This starts:
- `app` on port `5000`
- `mongo` on port `27017`

### Environment variables

Create a `.env` file or set these values in your host environment for production:
- `MONGODB_URI`
- `JWT_SECRET`
- `PORT` (optional, default `5000`)

### Notes

- The frontend is built in the first Docker stage.
- The backend serves the built frontend assets from `backend/frontend-dist`.
- In production, set `MONGODB_URI` to your managed MongoDB connection string.

## Production deployment options

You can deploy this app as a container to services like:
- Render
- Railway
- Fly.io
- DigitalOcean App Platform
- AWS ECS / Cloud Run

### Deploying to Render

This app ships as a single Docker container (API + built frontend). Render injects `PORT` automatically; you only need a MongoDB connection string and JWT secret.

#### 1. MongoDB (required)

Render does not host MongoDB. Create a free cluster on [MongoDB Atlas](https://www.mongodb.com/cloud/atlas):

1. Create a cluster and database user.
2. Under **Network Access**, allow `0.0.0.0/0` (or Render’s egress IPs if you restrict access).
3. Copy the connection string (e.g. `mongodb+srv://user:pass@cluster.mongodb.net/futurefs?retryWrites=true&w=majority`).

#### 2. Push code to GitHub

Render deploys from Git. Commit and push this repo (including `render.yaml`, `Dockerfile`, and app code) to GitHub on the branch you want to deploy (default: `main`).

#### 3. Deploy with a Blueprint (recommended)

1. Sign in at [render.com](https://render.com) and open **Blueprints**.
2. Click **New Blueprint Instance** and connect the GitHub repository.
3. Render reads `render.yaml` and creates the **future-fs-crm** web service.
4. When prompted, set **MONGODB_URI** to your Atlas connection string. **JWT_SECRET** can be auto-generated by the blueprint.
5. Click **Apply**. The first deploy builds the Docker image and may take several minutes.

#### 4. Deploy manually (alternative)

1. **New** → **Web Service** → connect the repo.
2. **Environment**: Docker, **Dockerfile path**: `Dockerfile`.
3. **Health check path**: `/health`.
4. Environment variables:
   - `MONGODB_URI` — Atlas connection string
   - `JWT_SECRET` — long random string (Render can generate one)
5. Create the service and wait for the deploy to finish.

#### 5. After deploy

- Open the service URL (e.g. `https://future-fs-crm.onrender.com`).
- Visit `/login` and use **First time setup** to create the admin account.
- Submit a test lead on `/` to confirm API + database connectivity.

**Notes**

- The frontend uses `window.location.origin` in production, so no `VITE_API_URL` is required when API and UI are served from the same host.
- Free/starter instances may spin down when idle; the first request after sleep can be slow.
- Check **Logs** in the Render dashboard if the deploy fails (often missing or invalid `MONGODB_URI`).

For other providers, build the Docker image and set the same environment variables.
